# Deploying the private demo

Three hosted pieces, all on free tiers:

```
Browser ──► Vercel (Next.js web app + access-code gate + server-side proxy holding the API token)
               │  HTTPS, Bearer token
               ▼
            Render (FastAPI + LangGraph agent, Docker)  ──► Groq · Langfuse · Slack
               │  asyncpg + SSL
               ▼
            Neon (PostgreSQL + pgvector)
```

The whole site sits behind an **access code**. Without it, every page redirects to a "Private demo" screen and every
API call is refused, so the link is useless to anyone you have not given the code to.

Takes about 30 minutes the first time. You need accounts on **GitHub**, **Neon**, **Render** and **Vercel**.

---

## 1. Put the code in a private GitHub repository

1. On github.com → **New repository** → name it (e.g. `revenue-recovery`) → **Private** → create, with no README.
2. In the project folder:

   ```bash
   git remote add origin https://github.com/<you>/revenue-recovery.git
   git push -u origin main
   ```

`.env`, `apps/web/.env.local` and local data are git-ignored, so no keys are pushed.

## 2. Database: Neon (free)

1. neon.tech → **New project** → region **AWS Asia Pacific (Singapore)** (same region as the API).
2. **Connect** → turn **Connection pooling off** (the API keeps its own pool; the pooler breaks prepared statements) →
   copy the connection string. It looks like
   `postgresql://user:password@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`.
   Paste it as-is; the API converts it for its driver.

pgvector is available on Neon; the first deploy creates the extension and all tables automatically.

## 3. API: Render

1. render.com → **New** → **Blueprint** → connect GitHub → pick the repository. Render reads `render.yaml`.
2. Fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string from step 2 |
   | `GROQ_API_KEY` | your Groq key |
   | `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` | your Langfuse keys (or leave empty to disable tracing) |
   | `SLACK_WEBHOOK_URL` | your Slack webhook (or leave empty) |
   | `APP_PUBLIC_URL`, `CORS_ORIGINS` | leave empty for now, filled in step 5 |

   `DEMO_API_TOKEN` is generated by Render. The blueprint uses the **Free** plan (no card): it sleeps after 15 minutes
   idle, so open the API health URL a minute before a demo to wake it. For an always-on demo, change the plan to
   **Starter** (~$7/month) in the service settings.
3. **Apply**. The first build takes ~10 minutes (it downloads the embedding and reranker models into the image).
4. Check `https://<your-service>.onrender.com/api/v1/health` shows `"status":"ok"` and `"database":true`.
5. Open the service → **Environment** → copy the value of `DEMO_API_TOKEN` (needed in step 4).

## 4. Web app: Vercel

1. vercel.com → **Add New** → **Project** → import the repository.
2. **Root Directory**: `apps/web` (Framework: Next.js is detected).
3. **Environment Variables**:

   | Variable | Value |
   |---|---|
   | `API_BASE_URL` | `https://<your-service>.onrender.com` |
   | `API_TOKEN` | the `DEMO_API_TOKEN` copied from Render |
   | `ACCESS_CODE` | the code you will give people, e.g. 3–4 random words. Long enough not to be guessed. |
   | `NEXT_PUBLIC_CONTACT_URL` | optional: your LinkedIn URL, shown as "Get in touch for access" |

4. **Deploy**. Note the URL, e.g. `https://revenue-recovery-xyz.vercel.app`.

## 5. Connect the two

In Render → Environment, set `APP_PUBLIC_URL` and `CORS_ORIGINS` to the Vercel URL, then **Save** (Render redeploys).
`APP_PUBLIC_URL` is where the buttons in Slack messages point.

## 6. Load the demo data

Open the Vercel URL → enter the access code → **Load demo dataset** in the header. The first load creates the
synthetic "Arcline Systems" workspace and indexes the policy documents (allow up to a minute). Then run the agent on
Vertex Industrial from the dashboard.

## Giving and revoking access

- Give someone the access code; their browser remembers it for 30 days.
- To revoke everyone: change `ACCESS_CODE` in Vercel and redeploy. Old cookies stop working immediately.
- Nobody, including people with the code, ever sees the API token or your keys: they stay on Vercel and Render.

## Costs

| Service | Plan | Cost |
|---|---|---|
| Vercel | Hobby | free |
| Neon | Free | free (0.5 GB, plenty for the demo) |
| Render | Free | free (sleeps when idle; Starter ~$7 / month for always-on) |
| Groq | Free tier | free; 8k tokens/min limits speed, not correctness |
| Langfuse | Hobby | free |

Pause the Render service from its dashboard when you are not demoing to stop billing.

## Troubleshooting

| Symptom | Fix |
|---|---|
| "Cannot reach the API" in the app | Render service sleeping (free plan) or `API_BASE_URL` wrong (no trailing `/api/v1`) |
| 401 on every page after entering the code | `ACCESS_CODE` changed: enter the new code |
| Load demo dataset says "unauthenticated" | `API_TOKEN` on Vercel must equal `DEMO_API_TOKEN` on Render |
| `prepared statement ... does not exist` | the Neon URL is the pooled one: use the direct connection string |
| Render "out of memory" / service restarts | set `RERANKER_ENABLED=false` in Render, or use the Starter plan |
| Agent recommendation says "rules fallback (rate limit)" | Groq free-tier minute limit: wait a minute between runs |
